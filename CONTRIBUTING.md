# Contributing

Thanks for helping. This project values **falsifiable, traceable claims** over impressive-sounding ones.

## Ground rules

1. **Every number comes from code.** Results are computed in `analysis.ipynb` (generated by
   `scripts/build_notebook.py`) and written to `results/results.json`. Written deliverables are rendered from
   `deliverables/templates/` by `scripts/render_deliverables.py`; never type a result number into a template.
   `scripts/check_numbers.py` fails CI on any number it cannot trace.
2. **Never weaken a test to make it pass.** The expected values in `tests/test_chsh.py` came from an independent
   hand derivation. If a value disagrees, re-derive it, decide which side is wrong, fix that side, and log the
   decision in `DECISIONS.md`.
3. **Keep the Python model and the browser model identical.** `site/model.js` is a line-for-line port of
   `src/chsh.py`; `tests/test_parity.py` checks them against each other to 1e-12. Change both together.
4. **Negative results and limitations stay.** If you overturn a claim, add a failing test first, then the fix,
   and update the memo's Limitations section and `DECISIONS.md`.
5. **Cite only sources you have checked**, with a page/equation/table anchor where possible.

## Development

```bash
python3.13 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m ruff check .
python -m pytest -q
scripts/package.sh          # notebook → results.json → deliverables → PDFs → submission.zip
python scripts/build_site.py --out _site && python -m http.server -d _site 8000
```

Figures are generated, never hand-edited. PDFs need `pandoc` and Node with Playwright/Chromium (no LaTeX).

## Pull requests

Keep PRs scoped. Include the test command and its output, which `results.json` keys changed (if any), and any
change to a limitation or assumption. CI must pass. `main` is the only long-lived branch: work on a short-lived
branch, open a PR, and delete the branch after merge.
